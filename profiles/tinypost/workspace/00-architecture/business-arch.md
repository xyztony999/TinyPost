## 第一部分：文档概述

本文档描述 TinyPost——轻量本地 API 客户端的业务架构。TinyPost 面向内网/信创环境的开发与联调人员，提供不上云、可离线使用的 HTTP 接口调试能力。

### 1.1 背景与目标

内网与信创环境（银河麒麟 V10 SP3）缺少可用的 API 调试工具：主流云客户端不可离线使用，浏览器受 CORS 与证书策略限制。TinyPost 的目标是把「构建请求 → 发送 → 检视 → 沉淀为可回放资产」的完整调试工作流收进一个本地桌面应用，数据全部存本机，敏感信息不出本机。

### 1.2 文档定位

| 定位 | 说明 |
|------|------|
| 本文档做什么 | 描述本地 API 调试域内 L2/L3/L4 的层级结构和业务关系，不涉及系统实现 |
| 本文档不做什么 | 不划分应用模块、不标注用户类型、不涉及技术选型和系统架构 |

### 1.3 层级定义

| 层级 | 名称 | 说明 |
|------|------|------|
| L1 | 业务域 | 系统所覆盖的业务范围 |

| L3 | 关键业务 | 各阶段内的关键业务能力 |

## 第二部分：业务架构

> 本章按 L2→L3→L4 逐层描述业务架构。每层有其概述和业务说明。

### 本架构概览

调试工作呈「运行态—定义态—边界」三段结构：调试执行是运行态阶段（单请求与整链，把请求定义一次性变成可观察的响应，任一步执行能力同源复用）；调试资产是定义态阶段（把执行依赖与产出组织为留存的本地资产——编著型的集合与环境、自动留档型的历史）；数据迁移与互操作是边界阶段（与外部工具生态及跨机器场景互通）。执行阶段一次性，资产阶段长期留存，边界阶段管进出。

### 2.1 调试执行（核心域）

**业务说明**：调试工作的运行态阶段——把可复用的请求定义变成一次性的执行与观察。覆盖单请求的构建发送与多请求整链的编排回放；链路每步复用单请求执行能力，执行产出（快照留档、提取回写）流入调试资产。

##### 2.1.1 请求构建与发送

**业务说明**：定义并执行一次 HTTP 调用：方法、URL、查询参数、请求头、请求体（原始文本/表单文件/URL 编码）、认证方式，经变量渲染后发出，并完整呈现响应。所属 L2：调试执行。

###### 2.1.1.1 请求编辑

**业务说明**：编辑方法/URL/查询参数/请求头/请求体/认证（Bearer、Basic、API Key）/TLS 选项，形成一份可保存、可复用的请求定义。所属 L3：请求构建与发送。

###### 2.1.1.2 请求执行

**业务说明**：发出前按激活环境完成 `{{变量}}` 渲染，随后执行请求；支持超时、跳过证书校验、跟随重定向等执行选项，可中途取消。所属 L3：请求构建与发送。

###### 2.1.1.3 响应检视

**业务说明**：呈现状态码、响应头、响应体（按内容类型格式化）、耗时、大小、重定向链与 Set-Cookie 事件。所属 L3：请求构建与发送。

###### 2.1.1.4 响应落盘

**业务说明**：将响应体（尤其二进制）另存为本机文件，保证下载类响应数据不损坏。所属 L3：请求构建与发送。

##### 2.1.2 集合运行

**业务说明**：把多个请求按业务顺序组织为链路（典型如内网登录链），一键按序回放，供联调与回归使用；运行对象（集合内请求项及其顺序）取自调试资产，提取回写结果流回调试资产。所属 L2：调试执行。

###### 2.1.2.1 运行编排

**业务说明**：确定参与运行的请求项集合——依拖拽顺序排列、可将部分请求项标记为不参与运行。所属 L3：集合运行。

###### 2.1.2.2 链路执行

**业务说明**：串行执行链路中参与运行的请求项，呈现每一步的请求/响应结果；任一步非 2xx 或二进制响应即停止推进。所属 L3：集合运行。

###### 2.1.2.3 提取回写

**业务说明**：按提取规则从响应中抽取值（如 token）写回环境变量，供链路后续请求使用。所属 L3：集合运行。

### 2.2 调试资产（支撑域）

**业务说明**：调试工作的定义态阶段——把编著与留档组织为可复用的本地资产：编著型资产（集合、环境）由用户主动维护，自动留档型资产（历史）随每次执行沉淀。资产在执行结束后长期留存，供再次执行、回放与迁移复用。

##### 2.2.1 集合管理

**业务说明**：以集合为单位组织请求定义（如按业务模块或链路分组），集合内请求项可排序、可维护。所属 L2：调试资产。

###### 2.2.1.1 集合维护

**业务说明**：集合的新建、改名、删除。所属 L3：集合管理。

###### 2.2.1.2 请求项维护

**业务说明**：请求项的保存、改名、删除，请求定义的持久化归档。所属 L3：集合管理。

###### 2.2.1.3 请求项排序

**业务说明**：拖拽调整集合内请求项的先后顺序，使集合语义（如登录链路顺序）显性化。所属 L3：集合管理。

##### 2.2.2 环境与执行上下文

**业务说明**：具名环境（如 dev/prod）承载参数化（变量）、身份（Cookie 罐）与通道安全（TLS 客户端证书），构成每次调试执行所处的上下文：变量在请求发出前渲染，Cookie 罐维持环境内跨请求登录态，证书满足双向认证；整个执行上下文随激活环境整体切换，实现一套请求定义多环境复用。所属 L2：调试资产。

###### 2.2.2.1 环境维护

**业务说明**：环境的新建、编辑、删除，内含变量清单、TLS 证书路径配置。所属 L3：环境与执行上下文。

###### 2.2.2.2 环境激活

**业务说明**：指定当前唯一生效的环境；变量取值、会话（Cookie 罐）与证书均随激活环境整体切换。所属 L3：环境与执行上下文。

###### 2.2.2.3 变量定义

**业务说明**：维护 `{{key}}` 形式的环境变量（如 baseUrl、token）。所属 L3：环境与执行上下文。

###### 2.2.2.4 Cookie 收集与携带

**业务说明**：按环境收集响应中的 Set-Cookie 并在后续匹配请求中自动携带，形成会话罐；不同环境会话互不污染。所属 L3：环境与执行上下文。

###### 2.2.2.5 TLS 客户端证书配置

**业务说明**：为环境配置客户端证书/密钥/CA 路径，满足双向认证内网接口的调试需要。所属 L3：环境与执行上下文。

##### 2.2.3 历史记录

**业务说明**：自动留存每次实际发送的完整快照（请求入参与响应出参），作为自动留档型资产支撑随时回看、回填复现与清理。所属 L2：调试资产。

###### 2.2.3.1 历史捕获

**业务说明**：每次发送后自动保存请求/响应快照、耗时与时间戳。所属 L3：历史记录。

###### 2.2.3.2 历史回填

**业务说明**：从历史条目一键把完整请求定义回填到编辑器复现当时的调用。所属 L3：历史记录。

###### 2.2.3.3 历史清理

**业务说明**：按需清除历史记录，控制本机数据留存。所属 L3：历史记录。

### 2.3 数据迁移与互操作（支撑域）

**业务说明**：与外部工具生态及跨机器迁移场景互通，避免资产锁定。

##### 2.3.1 导入导出

**业务说明**：把既有资产搬进 TinyPost 或把本地数据整体备份迁移。所属 L2：数据迁移与互操作。

###### 2.3.1.1 Postman 导入

**业务说明**：解析 Postman Collection v2.1 文件，导入集合、请求项与变量。所属 L3：导入导出。

###### 2.3.1.2 cURL 导入

**业务说明**：解析 cURL 命令行生成请求定义。所属 L3：导入导出。

###### 2.3.1.3 便携备份与恢复

**业务说明**：整库导出为单文件备份、从备份恢复，支撑跨机器迁移与数据保全。所属 L3：导入导出。

## 第三部分：业务架构树

> **由第二部分内容对应生成，第二部分任何变更必须同步更新本视图。** 结构：L1 > L2 > L3 > L4。

```
本地 API 调试域
├── 调试执行
│   ├── 请求构建与发送
│   │   ├── 请求编辑
│   │   ├── 请求执行
│   │   ├── 响应检视
│   │   └── 响应落盘
│   └── 集合运行
│       ├── 运行编排
│       ├── 链路执行
│       └── 提取回写
├── 调试资产
│   ├── 集合管理
│   │   ├── 集合维护
│   │   ├── 请求项维护
│   │   └── 请求项排序
│   ├── 环境与执行上下文
│   │   ├── 环境维护
│   │   ├── 环境激活
│   │   ├── 变量定义
│   │   ├── Cookie 收集与携带
│   │   └── TLS 客户端证书配置
│   └── 历史记录
│       ├── 历史捕获
│       ├── 历史回填
│       └── 历史清理
└── 数据迁移与互操作
    └── 导入导出
        ├── Postman 导入
        ├── cURL 导入
        └── 便携备份与恢复
```

### 附录A：L3 业务依赖关系

> 描述 L3 关键业务之间的上下游依赖关系，为后续应用架构中模块调用分析提供依据。

| 上游 L3 | 依赖方向 | 下游 L3 | 依赖说明 |
|---------|---------|---------|---------|
| 请求构建与发送 | → | 环境与执行上下文 | 发出前取激活环境变量渲染，并按环境取 Cookie 罐与客户端证书 |
| 请求构建与发送 | → | 历史记录 | 发送完成后写历史快照 |
| 集合运行 | → | 请求构建与发送 | 链路每步复用单请求执行能力 |
| 集合运行 | → | 环境与执行上下文 | 提取规则结果写回环境变量；执行时取渲染与会话上下文 |
| 导入导出 | → | 集合管理 | Postman/cURL 导入落为集合与请求项 |
| 历史记录 | → | 请求构建与发送 | 历史回填把完整请求定义回填到编辑器 |
| 导入导出 | → | 请求构建与发送 | cURL 导入解析结果回填请求编辑器 |
| 导入导出 | → | 环境与执行上下文 | Postman 导入把集合变量落为环境 |

### 附录B：业务术语表

> 统一业务术语定义，后续领域对象命名以此为准。

| 术语 | 定义 | 备注 |
|------|------|------|
| 请求 | 一次完整 HTTP 调用的定义（方法/URL/头/体/认证/扩展配置） | 可保存、可回放 |
| 集合 | 一组有序请求项的容器 | 按模块或链路组织 |
| 请求项 | 集合内单个请求及其顺序与参与运行标记 | |
| 环境 | 命名的一套变量 + TLS 证书 + Cookie 罐 | 同一时刻仅一个激活 |
| 执行上下文 | 激活环境在执行时刻提供的变量取值、Cookie 罐与 TLS 证书组合 | 随环境激活整体切换 |
| 变量 | `{{key}}` 模板占位，取值来自激活环境 | |
| 提取规则 | 从响应按 JSONPath 抽值写回变量的规则 | token 链路核心 |
| Cookie 罐 | 环境内共享的 Set-Cookie 存储 | 会话载体 |
| 集合运行 | 按序串行执行集合内启用请求项并回写提取结果 | 登录链回放 |
| 便携备份 | 整库单文件导出/恢复 | 跨机器迁移 |
| 历史 | 每次实际发送的完整快照 | 自动捕获，留档型资产 |
