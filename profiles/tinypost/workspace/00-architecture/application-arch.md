## 第一部分：文档概述

本文档将 TinyPost 业务架构（business-arch.md）映射为应用域、功能模块、功能子模块的层级结构，标注用户类型与模块间调用关系，为 PRD 与接口设计提供功能组织视图。

### 1.1 背景与目标

TinyPost 是单机桌面应用，无服务端与多角色协作。应用架构的目标是：把业务架构的 7 个 L3 按 DDD 四层归类组织，明确模块间调用方向，并显式补充系统级功能（应用设置）与纯技术能力（存储/传输/对话框/外壳），使后续接口（IPC 契约）设计有清晰的结构落点。

### 1.2 文档定位

| 定位 | 说明 |
|------|------|
| 本文档做什么 | 将业务架构映射为应用域、功能模块、功能子模块的层级结构，标注用户类型、模块间调用关系及应用域分层 |
| 本文档不做什么 | 不涉及具体功能点描述、不涉及系统详细设计、不涉及技术实现和部署方案 |

### 1.3 范围

| 范围 | 说明 |
|------|------|
| 业务域 | 本地 API 调试域 |
| 应用域 | 核心业务域、支撑业务域、基础数据域、平台支撑域（DDD 四层全覆盖） |
| 用户类型 | API 调试者（唯一） |

## 第二部分：应用架构

> 本章按应用域逐层描述功能模块与功能子模块。每个应用域有其概述，每个功能模块/子模块有功能说明及涉及用户类型。

### 本架构概览

四个应用域呈「双核驱动、五域支撑、一域配置、四平台件」结构：核心业务域承载调试主链（单请求构建发送、集合链路回放）；支撑业务域沉淀与维护调试资产（集合、环境、会话、历史、导入导出）；基础数据域仅应用设置；平台支撑域提供存储、HTTP 传输、系统对话框与应用外壳四项纯技术能力，不含业务语义。

### 应用域分层

> 按 DDD 战略设计，将应用域归入不同分层，决定后续详细设计的建模深度和投入策略。AA 应用域严格按照 DDD 四层划分，每个 BA L3 按 [L3 → DDD 四层归类原则](#l3--ddd-四层归类原则在本项目的应用) 归入对应分层。

| 分层 | 说明 | 包含功能模块 |
|------|------|-------------|
| 核心业务域 | 承载核心业务价值，有运行态流转和聚合根，深度建模 | 请求构建与发送（C-01）、集合运行（C-02） |
| 支撑业务域 | 为核心业务提供必要的业务支撑能力，包含业务规则，独立上下文 | 集合管理（S-01）、环境与变量（S-02）、会话保持（S-03）、历史记录（S-04）、导入导出（S-05） |
| 基础数据域 | 系统级引用数据，无业务状态机，薄适配 | 应用设置（D-01） |
| 平台支撑域 | 纯技术能力，零业务语义，可复用 | 本地存储引擎（P-01）、HTTP 传输引擎（P-02）、系统对话框服务（P-03）、应用外壳（P-04） |

> 归类依据：请求构建与发送、集合运行为调试主链环节（Q1 主链判定通过）；集合/环境/会话/历史/导入导出含业务规则且服务主链（Q2）；应用设置为纯配置（Q3）；存储/传输/对话框/外壳换任何行业可原样复用（Q4）。

### 2.1 核心业务域

**应用域概述**：调试价值的直接产生地——把「一次请求」与「一条链路」执行清楚。请求构建与发送拥有运行态（待发送→发送中→完成/失败/取消）与请求定义聚合；集合运行拥有链路执行语义与运行编排规则。服务的用户群体：API 调试者。

#### 2.1.1 请求构建与发送（C-01）

**功能说明**：定义并执行单次 HTTP 调用：编辑请求定义、按环境渲染变量后发出、完整检视响应、必要时落盘。

**涉及用户类型**：- [✓] API 调试者

##### 2.1.1.1 请求编辑

**功能说明**：编辑方法、URL、查询参数、请求头、请求体（raw/form-data/urlencoded）、认证（Bearer/Basic/API Key）与请求级 TLS 选项，形成请求定义。

**涉及用户类型**：- [✓] API 调试者

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 环境与变量 | 编辑态预览引用激活环境的变量取值 |

##### 2.1.1.2 请求执行

**功能说明**：发出前完成 `{{变量}}` 渲染，按执行选项（超时、跳过证书校验、跟随重定向）执行请求，支持取消；自动应用激活环境的 Cookie 罐与客户端证书。

**涉及用户类型**：- [✓] API 调试者

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 环境与变量 | 取激活环境变量完成渲染 |
| 会话保持 | 取环境 Cookie 罐与 TLS 客户端证书 |
| 历史记录 | 发送完成后写入历史快照 |

##### 2.1.1.3 响应检视

**功能说明**：呈现状态码/响应头/响应体（按 Content-Type 格式化）/耗时/大小/重定向链/Set-Cookie 事件，识别二进制响应。

**涉及用户类型**：- [✓] API 调试者

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 会话保持 | 展示 Set-Cookie 对 Cookie 罐的影响 |

##### 2.1.1.4 响应落盘

**功能说明**：将响应体另存为本机文件，二进制响应不走文本渲染，保证下载数据完整。

**涉及用户类型**：- [✓] API 调试者

**调用关系**：

*（无跨业务模块调用；文件对话框属平台支撑服务）*

#### 2.1.2 集合运行（C-02）

**功能说明**：按集合内请求项顺序串行执行链路（典型：内网登录链），执行中提取响应值回写环境变量供后续请求使用，实现离线整链回放。

**涉及用户类型**：- [✓] API 调试者

##### 2.1.2.1 运行编排

**功能说明**：确定参与运行的请求项——沿用请求项排序结果，可将部分请求项标记为不参与运行（meta.runEnabled）。

**涉及用户类型**：- [✓] API 调试者

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 集合管理 | 读取集合内请求项及其顺序与跳过标记 |

##### 2.1.2.2 链路执行

**功能说明**：串行执行参与运行的请求项，逐步呈现请求/响应结果；任一步非 2xx 或二进制响应即停止推进，也可手动中止。

**涉及用户类型**：- [✓] API 调试者

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 请求构建与发送 | 每一步复用单请求执行能力（渲染/发送/检视/留档） |

##### 2.1.2.3 提取回写

**功能说明**：每步执行后按该请求的提取规则（JSONPath）从响应抽值写回环境变量。

**涉及用户类型**：- [✓] API 调试者

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 环境与变量 | 提取结果写回激活环境变量 |

### 2.2 支撑业务域

**应用域概述**：为核心业务沉淀可复用资产——请求定义的组织（集合管理）、多环境复用基础（环境与变量）、登录态维持（会话保持）、调试留档（历史记录）、生态互通（导入导出）。每个模块含独立业务规则（环境互斥、Cookie 隔离、导入映射等）。

#### 2.2.1 集合管理（S-01）

**功能说明**：以集合为单位组织请求项，维护集合与请求项的生命周期及顺序。

**涉及用户类型**：- [✓] API 调试者

##### 2.2.1.1 集合维护

**功能说明**：集合的新建、改名、删除（删除集合级联删除其请求项）。

**涉及用户类型**：- [✓] API 调试者

**调用关系**：

*（无跨业务模块调用）*

##### 2.2.1.2 请求项维护

**功能说明**：请求项的保存、改名、删除；请求定义持久化归档与再加载。

**涉及用户类型**：- [✓] API 调试者

**调用关系**：

*（无跨业务模块调用）*

##### 2.2.1.3 请求项排序

**功能说明**：拖拽调整集合内请求项顺序（sort_order 持久化），顺序即链路执行顺序。

**涉及用户类型**：- [✓] API 调试者

**调用关系**：

*（无跨业务模块调用）*

#### 2.2.2 环境与变量（S-02）

**功能说明**：具名环境管理变量清单、TLS 证书路径与 Cookie 罐归属；同一时刻仅一个环境激活（TP-BR-04）。

**涉及用户类型**：- [✓] API 调试者

##### 2.2.2.1 环境维护

**功能说明**：环境的新建、编辑、删除；含变量清单与 TLS 证书路径配置。

**涉及用户类型**：- [✓] API 调试者

**调用关系**：

*（无跨业务模块调用）*

##### 2.2.2.2 环境激活

**功能说明**：切换当前唯一激活环境；变量取值、会话、证书随之整体切换。

**涉及用户类型**：- [✓] API 调试者

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 会话保持 | 激活切换即切换 Cookie 罐与证书上下文 |

##### 2.2.2.3 变量定义

**功能说明**：维护环境变量（`{{key}}` 占位的取值来源）。

**涉及用户类型**：- [✓] API 调试者

**调用关系**：

*（无跨业务模块调用）*

#### 2.2.3 会话保持（S-03）

**功能说明**：在环境内维持跨请求登录态：Cookie 罐按环境隔离（TP-BR-05），TLS 客户端证书支撑双向认证内网接口。

**涉及用户类型**：- [✓] API 调试者

##### 2.2.3.1 Cookie 收集与携带

**功能说明**：收集响应 Set-Cookie 入罐；请求发出前按 URL 匹配携带。

**涉及用户类型**：- [✓] API 调试者

**调用关系**：

*（无跨业务模块调用；被请求构建与发送调用）*

##### 2.2.3.2 TLS 客户端证书配置

**功能说明**：环境级客户端证书/密钥/CA 路径配置与请求时应用。

**涉及用户类型**：- [✓] API 调试者

**调用关系**：

*（无跨业务模块调用）*

#### 2.2.4 历史记录（S-04）

**功能说明**：自动留存每次实际发送的完整快照，支撑回看、复现与清理。

**涉及用户类型**：- [✓] API 调试者

##### 2.2.4.1 历史捕获

**功能说明**：每次发送后自动保存请求/响应快照、耗时与时间戳，无需人工触发。

**涉及用户类型**：- [✓] API 调试者

**调用关系**：

*（无跨业务模块调用；被请求构建与发送调用写入）*

##### 2.2.4.2 历史回填

**功能说明**：从历史条目一键回填完整请求定义到编辑器。

**涉及用户类型**：- [✓] API 调试者

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 请求构建与发送 | 回填目标为请求编辑器 |

##### 2.2.4.3 历史清理

**功能说明**：清空历史，控制本机数据留存。

**涉及用户类型**：- [✓] API 调试者

**调用关系**：

*（无跨业务模块调用）*

#### 2.2.5 导入导出（S-05）

**功能说明**：与 Postman/cURL 生态互通，便携备份支撑跨机器迁移；所有解析为纯前端逻辑，落库走集合管理。

**涉及用户类型**：- [✓] API 调试者

##### 2.2.5.1 Postman 导入

**功能说明**：解析 Postman Collection v2.1，导入集合、请求项与变量。

**涉及用户类型**：- [✓] API 调试者

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 集合管理 | 导入结果落为集合与请求项 |
| 环境与变量 | 导入集合变量到环境 |

##### 2.2.5.2 cURL 导入

**功能说明**：解析 cURL 命令行生成请求定义并进入编辑器。

**涉及用户类型**：- [✓] API 调试者

**调用关系**：

| 调用模块/子模块 | 调用说明 |
|---------------|---------|
| 请求构建与发送 | 解析结果回填请求编辑器 |

##### 2.2.5.3 便携备份与恢复

**功能说明**：整库导出为单文件备份、从备份恢复全部数据。

**涉及用户类型**：- [✓] API 调试者

**调用关系**：

*（无跨业务模块调用；读写存储引擎属平台支撑服务）*

### 2.3 基础数据域

**应用域概述**：系统级配置数据，读多写少，无业务状态机。

#### 2.3.1 应用设置（D-01）

**功能说明**：全局执行选项与应用偏好：请求超时、跳过 TLS 校验开关（默认关闭，开启须可见，TP-BR-08）、跟随重定向、明暗主题（跟随系统）。

**涉及用户类型**：- [✓] API 调试者

**调用关系**：

*（无跨业务模块调用；被请求构建与发送读取执行选项）*

### 2.4 平台支撑域

**应用域概述**：纯技术能力，零业务语义。BA 不含对应节点（BA 不涵盖纯技术功能），为完整性在 AA 显式列出。

#### 2.4.1 本地存储引擎（P-01）

**功能说明**：sql.js(SQLite WASM) 数据库生命周期管理与通用 CRUD/事务通道封装；5 张表（request_history/environments/collections/saved_requests/settings）的表结构由各业务模块定义——本模块持有 schema 而不含业务规则，仍满足 Q4 零业务语义。

**涉及用户类型**：- [✓] API 调试者

**调用关系**：

*（平台支撑服务，不标注跨模块调用）*

#### 2.4.2 HTTP 传输引擎（P-02）

**功能说明**：主进程 Node http/https 封装：超时、重定向跟随、自签证书（insecure）、客户端证书、multipart/urlencoded 编码、请求取消、响应元信息（耗时/大小/重定向链/Set-Cookie）。

**涉及用户类型**：- [✓] API 调试者

**调用关系**：

*（平台支撑服务，不标注跨模块调用）*

#### 2.4.3 系统对话框服务（P-03）

**功能说明**：原生文件对话框：响应另存为、文件选择与读取（导入/multipart 文件字段）、备份保存与恢复选择。

**涉及用户类型**：- [✓] API 调试者

**调用关系**：

*（平台支撑服务，不标注跨模块调用）*

#### 2.4.4 应用外壳（P-04）

**功能说明**：Electron 窗口生命周期、preload 桥、IPC 通道注册分发、明暗主题跟随系统、双平台打包（Windows x64 / 麒麟 arm64 AppImage+deb）。

**涉及用户类型**：- [✓] API 调试者

**调用关系**：

*（平台支撑服务，不标注跨模块调用）*

## 第三部分：应用架构树

> **由第二部分内容对应生成，第二部分任何变更必须同步更新本视图。** 结构：应用域 > 功能模块 > 功能子模块（含功能说明）。

```
TinyPost
├── 核心业务域
│   ├── 请求构建与发送 (C-01)
│   │   ├── 请求编辑 — 编辑方法/URL/头/体/认证/TLS 形成请求定义
│   │   ├── 请求执行 — 变量渲染后按执行选项发送，支持取消
│   │   ├── 响应检视 — 状态/头/体/耗时/重定向链/Set-Cookie 呈现
│   │   └── 响应落盘 — 响应体（含二进制）另存为本机文件
│   └── 集合运行 (C-02)
│       ├── 运行编排 — 确定参与运行的请求项（顺序+跳过标记）
│       ├── 链路执行 — 串行执行链路并逐步呈现结果
│       └── 提取回写 — JSONPath 提取响应值写回环境变量
├── 支撑业务域
│   ├── 集合管理 (S-01)
│   │   ├── 集合维护 — 集合新建/改名/删除
│   │   ├── 请求项维护 — 请求项保存/改名/删除
│   │   └── 请求项排序 — 拖拽排序，顺序即执行顺序
│   ├── 环境与变量 (S-02)
│   │   ├── 环境维护 — 环境新建/编辑/删除（含变量、TLS 配置）
│   │   ├── 环境激活 — 唯一激活环境切换
│   │   └── 变量定义 — {{key}} 环境变量维护
│   ├── 会话保持 (S-03)
│   │   ├── Cookie 收集与携带 — 环境 Cookie 罐自动收集与匹配携带
│   │   └── TLS 客户端证书配置 — 双向认证证书按环境配置
│   ├── 历史记录 (S-04)
│   │   ├── 历史捕获 — 发送后自动留档完整快照
│   │   ├── 历史回填 — 历史一键回填编辑器
│   │   └── 历史清理 — 清空历史
│   └── 导入导出 (S-05)
│       ├── Postman 导入 — Collection v2.1 解析导入
│       ├── cURL 导入 — 命令行解析为请求定义
│       └── 便携备份与恢复 — 整库单文件备份/恢复
├── 基础数据域
│   └── 应用设置 (D-01) — 超时/insecure/重定向/主题
└── 平台支撑域
    ├── 本地存储引擎 (P-01) — sql.js 数据库与 5 表 CRUD
    ├── HTTP 传输引擎 (P-02) — 主进程 http/https 传输能力
    ├── 系统对话框服务 (P-03) — 原生文件对话框
    └── 应用外壳 (P-04) — 窗口/IPC 分发/主题/打包
```

## 附录

### L3 → DDD 四层归类原则在本项目的应用

| BA L3 | 判定路径 | 归类 |
|-------|---------|------|
| 请求构建与发送 | Q1 主链（调试主环节、运行态流转）| 核心业务域 |
| 集合运行 | Q1 主链（链路回放为产品核心场景，执行编排语义）| 核心业务域 |
| 集合管理 / 环境与变量 / 会话保持 / 历史记录 / 导入导出 | Q2 含业务规则且被主链调用 | 支撑业务域 |
| （系统级）应用设置 | Q3 纯配置无状态机 | 基础数据域 |
| （系统级）存储/传输/对话框/外壳 | Q4 零业务语义 | 平台支撑域 |

### 模块编码表（X-MM[-SS]）

| 编码 | 模块（子模块 SS 分配） |
|------|----------------------|
| C-01 | 请求构建与发送（01 请求编辑 / 02 请求执行 / 03 响应检视 / 04 响应落盘） |
| C-02 | 集合运行（01 运行编排 / 02 链路执行 / 03 提取回写） |
| S-01 | 集合管理（01 集合维护 / 02 请求项维护 / 03 请求项排序） |
| S-02 | 环境与变量（01 环境维护 / 02 环境激活 / 03 变量定义） |
| S-03 | 会话保持（01 Cookie 收集与携带 / 02 TLS 客户端证书配置） |
| S-04 | 历史记录（01 历史捕获 / 02 历史回填 / 03 历史清理） |
| S-05 | 导入导出（01 Postman 导入 / 02 cURL 导入 / 03 便携备份与恢复） |
| D-01 | 应用设置（00，无子模块） |
| P-01~P-04 | 存储引擎 / 传输引擎 / 对话框服务 / 应用外壳（均 00，无子模块） |

> 子模块编码即 `X-MM-SS`；NN（菜单项序号）在 D4 PageSpec 菜单引用处按需分配。
